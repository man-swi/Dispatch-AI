## 📈 System Workflow & Pipeline Architecture

```
[ Delay Incident Caught ] ──> ( Ingest Webhook Target )
                                          │
                                          ▼
[ Driver Voice Channel ] <── ( Fetch Target Meta Profile )
         │
         ▼
[ Whisper Parsing Engine ] ──> [ Mistral Analytical Framework ]
                                          │
                                          ▼
[ Cascade Escalation ] <── [ Rule Matrix Severity Filter ]
         │                                 │
         │ (Critical Flag)                 │ (Standard Route)
         ▼                                 ▼
( Human Operations Intercept )   ( Direct Status Mutation )
                                          │
                                          ▼
[ Historic Logs Updated ] <── ( Customer Alert Dispatched )

```

1. **Incident Triggers:** Delivery state calculations reveal a system anomaly or missed tracking target checkpoint. A secure REST webhook payload kicks off the n8n runner orchestration.
2. **Context Resolution:** The ingestion runner targets the FastAPI backend over standard secure channels to isolate profile details matching driver data arrays, routing indexes, and historical patterns.
3. **Interactive Vocal Contact:** An out-of-band communication pipeline addresses the field agent using dynamic programmatic voice text built by the acoustic engine synthesis layer.
4. **Speech-to-Text Ingestion:** The voice payload generated by the driver answers the system prompt. It is isolated and piped through Whisper models to be mapped directly into raw semantic structures.
5. **Cognitive Logic Parsing:** Mistral structures the raw unstructured translation data down into explicit parameter pairs containing target parameters (`delay_reason`, `updated_eta`, `severity`).
6. **Dynamic Matrix Rules Engine:** The system parses the output parameters against defined operational bounds:
* **Minor Delay (< 30m):** Suppresses alerts; shifts tracking windows forward inside database matrices.
* **Standard Incident (30m - 2h):** Triggers auto-notifications to customer interfaces, updates delivery tables.
* **Critical System Anomaly (> 2h / Broken Down / Driver Offline):** Automatically triggers high-priority operational flags, bypassing default delays to drop raw incidents onto emergency operations panels.


7. **Downstream Synchronization:** Data state entities across relational environments update instantly. State summaries feed back through downstream notification protocols while live web views update in real time.

## 💾 Relational Data Layer Blueprint

### 1. Table: `shipments`

Maintains operational state properties across monitored delivery runs.

| Physical Column | Data Engine Type | Structural Validation Constraints |
| --- | --- | --- |
| `shipment_id` | `TEXT` | `PRIMARY KEY`, Unique UID String format |
| `driver_name` | `TEXT` | `NOT NULL`, Character array string structure |
| `status` | `TEXT` | Status Check Constraints (`In-Transit`, `Delayed`, `Arrived`) |
| `expected_eta` | `TIMESTAMP` | System Target Checkpoint Window UTC |
| `updated_eta` | `TIMESTAMP` | Mutated Prediction Window modified by AI Extraction UTC |
| `delay_reason` | `TEXT` | Extracted structural category code strings |
| `severity` | `TEXT` | Engine Class Output (`low`, `medium`, `high`, `critical`) |

### 2. Table: `call_logs`

Asynchronous pipeline logging tracing all driver interaction workflows.

| Physical Column | Data Engine Type | Structural Validation Constraints |
| --- | --- | --- |
| `call_id` | `TEXT` | `PRIMARY KEY`, Transactional Identifier string |
| `shipment_id` | `TEXT` | `FOREIGN KEY` references `shipments.shipment_id` |
| `transcript` | `TEXT` | Plaintext output returned from Whisper execution layer |
| `extracted_summary` | `TEXT` | Operational plain language description built by Mistral LLM |
| `escalation_required` | `BOOLEAN` | Hard conditional bypass operational indicator flag |

### 3. Table: `incident_history`

Aggregated analytic tables measuring historical system routes over time to identify anomalies.

| Physical Column | Data Engine Type | Structural Validation Constraints |
| --- | --- | --- |
| `incident_id` | `TEXT` | `PRIMARY KEY`, Unique historical logging key string |
| `shipment_id` | `TEXT` | `FOREIGN KEY` references `shipments.shipment_id` |
| `route_id` | `TEXT` | Tracking segment code identifier string |
| `resolved_at` | `TIMESTAMP` | Operational timestamp tracking case clearance UTC |
| `resolution_type` | `TEXT` | Categorization string (`Automated`, `Human-Intervention`) |

## 🚀 Production Infrastructure Deployment Matrix

### FastAPI Service Engine (Railway Production Cluster)

* Automatic continuous integration tracking your source repository core branch.
* Environment variables injected at runtime manage private connection strings safely.
* Production-grade asynchronous workers handle concurrent tasks with high throughput.

### Streamlit Controls Interface (Streamlit Enterprise Cloud Platform)

* Connects directly to the repository layout target files to instantly serve interactive dashboards.
* Real-time network interfaces pool data via HTTP polling to display telemetry instantly.

### n8n Task Automations (Local Service / Secure Tunnel Network Infrastructure)

* Runs as an independent, persistent process with high performance inside your core operational environment.
* Generates secure, low-latency, tunnel endpoints to process inbound API notifications seamlessly.
* Embedded credentials management securely handles access keys for Mistral, Whisper, and ElevenLabs.
